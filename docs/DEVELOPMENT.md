# 本地与 API 双模式 AI 陪伴项目开发文档

版本：0.2 · 日期：2026-10-19 · 项目暂名：Local Companion

本文是独立可执行的开发交接规格。实施负责人：GPT-6.1 Sol，推理强度 High。面向 Windows 用户，中文交互。文中的文件路径均为项目内建议结构；以实现后的 README 为最终操作入口。

## 1. 用户目标与已确认决定

- 在自己的 Windows 电脑上运行专属 AI 女友，通过微信 ClawBot 与 OpenClaw 连接。
- 同时支持本地大模型与远程模型 API，可明确选择和切换。
- 用户选择的 API 类型为“其他服务商或中转 API”，因此必须支持自定义服务地址与模型 ID，不能固定到 DeepSeek 或任何单一厂商。
- 用户明确指定本地默认模型为 `qwen3:8b`，不得擅自改为 Qwen3.5。
- 人物设定、用户偏好和长期记忆跨模型保留。
- 后续希望上传 GitHub。本次交付可运行源代码、开发文档、操作说明和验证结果；尚未指定远程仓库，不自动发布。
- 0.1 提供中文命令行；用户后续明确要求 0.2 新增 Windows 可视化桌面界面，包含模型切换、角色设定、一键启动。微信仍是最终聊天入口。

## 3. MVP 范围与完成定义

第一版必须具备：

1. 可安装或检测的 OpenClaw 运行环境，以及单独的 companion 实例/状态目录，不覆盖用户已有默认配置。
2. `local`、`api` 两种模型模式，统一人物与记忆；可配置 API base URL、model ID 和密钥来源。
3. 中文健康检查：Node、Ollama、指定模型、OpenClaw、配置有效性、微信插件/绑定状态。
4. 中文启动和停止操作、模型切换、模型连通性测试、配置初始化。
5. 一套可修改的成年人 AI 恋人人物模板、用户偏好模板、记忆规则。
6. 可实际进行本地文字对话；优先通过 OpenClaw 验证完整角色链路。直接调用 Ollama 的测试必须明确标为模型测试，不冒充微信/OpenClaw 已接通。
7. 微信官方通道安装/登录入口与逐步操作文档。扫码必须由用户完成，不能报告未进行的绑定为成功。
8. 适合 GitHub 发布的干净源码，测试、示例配置、忽略规则、许可说明与第三方来源说明。

0.2 已新增图形配置界面，详见 DESKTOP.md。第二阶段：语音识别与合成、人物图片、更复杂的主动关心。MVP 不承诺微信实时语音电话、永久可用的主动推送、多用户服务或模型微调。

## 4. 架构与技术选择

```text
微信 ClawBot
    ↕ 腾讯微信通道插件
本机 OpenClaw Gateway / companion 角色
    ├─ 共用人物与记忆工作区
    ├─ local → Ollama 原生 API → qwen3:8b
    └─ api   → 用户指定的远程模型 API

项目启动器：环境检测、配置生成、模型切换、启动/停止、诊断与发布检查
```

以 OpenClaw 承担会话、通道、角色与工具调用。项目实现薄的配置/启动/验证层，不重新发明微信协议，也不开发未经验证的第三方微信逆向桥。

建议启动器使用 Node.js ESM 与内置模块，减少依赖；PowerShell 仅作为便捷入口。允许开发者基于实际依赖约束调整。外部依赖固定经过验证的版本并提供锁文件。依赖安装失败也应保留可用的源码、清晰诊断和手动步骤，禁止把未测试配置宣称为可用。

所有后台启动隐藏窗口，记录本项目进程归属；停止命令只能停止本项目启动的进程，不得杀掉用户全局 Ollama 或其他 OpenClaw 实例。

## 5. 双模式模型接入

### 5.1 本地模式

- 默认 endpoint：`http://127.0.0.1:11434`，使用 Ollama 原生 `/api/chat`。
- 默认 model：`qwen3:8b`；先 `/api/tags` 检查，缺失时给出明确提示，不静默下载。
- OpenClaw Ollama provider 使用 `api: "ollama"`；base URL 不追加 `/v1`。
- 默认关闭模型思考（以当前 Ollama/OpenClaw 兼容字段为准并实测），只向用户输出回复正文。
- 不盲目启用模型宣称的最大上下文。直接 Ollama 冒烟可从 8192 tokens 开始；OpenClaw 可能要求更大的最小上下文，必须按实际版本校验与显存测试确定，不能以虚报 contextWindow 绕过限制。
- 默认单并发、短回复、有限历史与检索记忆。记录冷启动与热请求时间，不预先保证 tokens/s。
- 本地模式不得自动调用云端模型、远程嵌入或联网搜索；故障时明确报错。必要的微信收发网络与模型推理网络分别说明。

### 5.2 API 模式

- MVP 支持 OpenAI-compatible Chat Completions 协议（可供兼容的国内外模型服务使用）；这里是协议兼容，不绑定某一个厂商。
- 配置必须包含 base URL、model ID、API key 环境变量名、上下文/输出限制、超时。真实密钥只来自运行时环境或明确忽略的本地私有文件。
- 远程 endpoint 默认要求 HTTPS；测试用 loopback HTTP 可以允许。拒绝 URL 中嵌入用户名/密码，诊断不打印 Authorization 或请求原文。
- 不把字符串 `API_KEY` 当成真实密钥，不把未替换示例 URL 当成可用配置。
- API 未配置时本地仍能启动；选择 API 模式时校验必要字段，给出中文错误。
- 首次启用 API 时清楚显示：当前角色设定、相关记忆与所需对话上下文将发给所选服务商。由明确的模式选择/设置动作记录知情启用，不重复骚扰确认。
- 本地故障不自动切到 API；API 故障不静默更换模型。可在未来添加由用户显式启用的降级策略。
- 处理超时、401/403、429、5xx、空回复、错误响应结构；重试有界，避免重复计费和重复微信回复。

### 5.3 切换行为

- 切换只改变 provider/model，不重建人物文件和记忆工作区。
- 切换前验证目标配置；失败保持原模式及原配置完整。
- 配置写入使用原子替换，首次生成与后续修改分开。重复初始化不得覆盖用户已修改的人物设定。
- 若 Gateway 需要重载/重启，脚本明确执行或提示；不能仅修改一个未被运行进程使用的文件。

## 6. 人物与记忆

模板名暂用“晚晴”，可改；成年女性设定，中文自然短句、温柔机灵、有独立观点，亲密称呼由用户决定。诚实表达 AI 身份，不编造真实线下共同经历，不因用户离线或暂停聊天而施压。

建议模板包括 `IDENTITY.md`、`SOUL.md`、`AGENTS.md`、`USER.md`、`MEMORY.md`，使用当前 OpenClaw 实际支持的目录约定。模板只含虚构示例，实际个人数据放入私有运行目录。

- 稳定偏好写入用户资料；重要约定写入长期记忆；短期事项写入带日期的记录。
- 明确区分用户表达、模型推测和角色虚构；未经确认的猜测不晋升为事实。
- 提供记住、查看、纠正、遗忘的操作说明或可靠命令入口。
- 新会话和切换模型后应能读取已保存偏好。
- “遗忘”明确作用范围：删除持久记忆并更新索引；旧会话转录、备份和微信记录若未同步删除，必须诚实说明，不承诺全链路抹除。检索不得从被排除的旧记录重新注入已遗忘信息。
- 只给角色必需的记忆读写工具；不能依靠提示词限制任意主机文件或命令。按实际 OpenClaw 能力设置目录/工具边界；无法可靠隔离时缩小工具集合并记录限制。

## 7. 微信与运行边界

- 使用腾讯维护的 `@tencent-weixin/openclaw-weixin`，channel ID `openclaw-weixin`。
- 先验证 OpenClaw/插件版本兼容，再安装和扫码。不使用任意网页上的“同名插件”。
- 从扫码结果/实际通道状态确定绑定成功，不采集或在文档中展示 token。
- 核对实际版本的发送者访问限制；官方文档记录过 2.4.8 与标准 pairing 存储不兼容的问题，不得盲目认为执行 pairing approve 就完成隔离。
- 仅绑定用户自己的会话，避免与工作助手共享记忆。通道绑定到 companion 角色。
- 网关管理接口只监听 loopback；不为连接微信而开放公网管理端口。
- 本地电脑休眠/关机会离线；提供手动启动和可选开机启动说明，不擅自更改系统睡眠设置。
- 主动问候先默认关闭。微信主动发送存在会话凭据时效的实际问题，后续启用须做投递检查、免打扰、限频和失败记录；不能保证任意时间可推送。

## 8. 仓库和数据布局

建议源码目录：

```text
local-companion/
  README.md
  package.json / package-lock.json
  .gitignore
  .env.example
  src/                   配置、provider、运行管理和诊断
  scripts/               Windows 便捷入口（如需要）
  templates/             无隐私的人物模板和配置示例
  tests/                 模式隔离、故障、配置写入等核心测试
  docs/
    DEVELOPMENT.md       本文
    HANDOFF.md           执行交接清单
    VALIDATION.md        实际验证结果与未完成项
```

实际状态目录应位于源码仓库外。开发期间可用当前工作目录下 `work/companion-state`；发布版本默认路径由初始化命令清楚显示且允许覆盖。依赖和临时安装产物不得混进用户下载的发布包。

GitHub 仅提交源码、模板和文档；排除密钥、微信凭据、真实 USER/MEMORY 文件、会话、日志、备份、模型权重、node_modules 和安装缓存。发布检查应扫描实际将提交/打包的文件，不只检查 .gitignore 是否存在。Windows 程序作为独立 Release 附件发布，必须省略本机 local-launch.json 和任何私有状态。

## 9. 建议用户操作接口

具体命令可由实现者调整，但 README 必须给出经过执行验证的完整命令。建议提供：

- `doctor`：检查运行环境和配置，输出可操作建议，不自动修复系统全局状态。
- `init`：创建私有工作区、角色模板、默认 local 配置；可重复执行。
- `models`：列出本地实际安装模型。
- `mode local` / `mode api`：明确切换并保留人物/记忆。
- `test-model`：对当前模型做简短请求，显示模式、模型、耗时，隐藏思考与密钥。
- `chat`：通过 OpenClaw 与角色对话或提供经过验证的原生 CLI 入口。
- `start` / `stop` / `status`：管理本项目实例。
- `wechat setup` / `wechat login`：检查插件、调用正规扫码入口并显示真实状态。
- `release-check`：检查待发布文件、示例可用性和敏感数据遗漏。

## 11. 实施顺序

1. 阅读本文，先报告歧义/版本冲突，再自行解决普通实现选择。
2. 确认本地实际依赖版本与官方 schema/CLI；创建独立源码与状态目录。
3. 实现双模式配置、模板生成、隔离与诊断。
4. 实现模型测试、OpenClaw 配置与运行管理、微信接入入口。
5. 测试真实 qwen3:8b；模拟 API 正常和异常路径；尽可能验证 OpenClaw 本地角色链路。
6. 写 README 和 VALIDATION，扫描源码，生成不含私有数据的可交付项目包。

安装 OpenClaw、插件等任务相关可逆依赖在授权范围内，优先项目隔离安装。网络/权限失败应先排查并采用安全替代方式；不能为了演示虚构已安装结果。无需等待 API 密钥或微信扫码才实现其他部分。
