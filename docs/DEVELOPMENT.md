# 当前架构与维护约定

版本：0.4.1。日期：2026-10-20（Asia/Taipei）。

## 产品范围

Windows 桌面控制台，通过腾讯微信插件与 OpenClaw 聊天。可选择本地 Ollama 或兼容 Chat Completions 的 API。两种模式分别保存模型与生成参数，共用当前人物、用户资料与明确提交的长期记忆；不自动从本地切到云端。

阅读代码从 [源码导读](CODEMAP.md) 开始，操作见 [README](../README.md)，验证边界见 [VALIDATION](VALIDATION.md)。

## 数据边界

源码和公开发行包不包含私人配置、角色、聊天、日志或密钥。运行数据由 COMPANION_HOME 或便携程序旁 local-launch.json 指定；缺省在用户目录 .local-companion。Windows API 密钥由 Electron safeStorage 加密，Node 后台只在内存中使用解密后的配置密钥。

本地子进程不会继承常见云端密钥。API 模式只传入配置要求的密钥。日志和错误应脱敏；发布前执行 release-check。

## 配置与角色事务

先校验目标配置，停止已确认归属的实例，再写文件并重启；失败时恢复旧配置及已归档角色状态。角色变更轮换短期会话，长期记忆保留。SQLite 文件归档与中央登记撤销必须配套，避免失效路径导致启动迁移失败。

模型切换保留角色与记忆；用户编辑提示词也不是模型学习或微调。提问规则、示例和称呼由角色文本控制，不靠删问号处理输出。

## 服务生命周期

监督器持有准确 ChildProcess，控制接口有随机令牌与实例标识。停止使用私有 IPC 让 Gateway 自身执行 SIGTERM 清理；65 秒超时后才强制终止持有的子进程。不能按磁盘保存的 PID 盲目杀进程。

启动和界面读取经过认证的 /readyz，包括微信失败和暂停信息。OpenClaw 的异常重启保护保留，不自动绕过。停止后等待五分钟可以让旧异常窗口自然过期；持续故障仍需查日志。

## 微信聊天节奏

gateway-control 在 Gateway 同一进程注册 Node 模块加载适配。只接入固定腾讯 2.4.10 的 dist/src/monitor/monitor.js 和 dist/src/messaging/process-message.js。检查包版本和唯一代码锚点，结构变化时明确报错；第三方安装文件保持原样。

适配层只接受已绑定所有者。连发文字默认等待 1.8 秒，最长等待六秒；合并后的文本放入一个原生 text_item，保留最新上下文令牌。媒体、引用及命令不与普通文字合并。每个会话串行调用原生处理流程。

发送前清理思考块和路由标签，按自然换行最多分三条，默认间隔一秒；代码块和列表不拆，超出的内容并入末条。新消息会取消旧回复未发出的部分，停止或账户中止会取消缓冲任务。已开始的模型推理不一定能中止，已发出的消息不能撤回。队列只驻留内存，不保证进程异常退出后的补发，不能自动重试无法确认的投递。

升级 Node、OpenClaw 或微信插件前，必须运行 chat-native-smoke，不能只看模型测试按钮。

## 模型与生成参数

本地/API 各自维护 temperature、contextWindow、maxTokens、timeoutMs。界面不强制某一厂商或模型 ID，服务商能力以实际兼容性为准；不要给所有 API 硬加 Ollama 专用参数。Ollama 的 num_ctx 仅用于本地原生调用。

新安装沿用保守的默认模型，不替用户下载权重或更改现有选择。私人用户可以自行选择 Qwen3.5 9B 或 API；公开模板不带其账号和个人姓名。

## 主动联系与记忆

主动联系默认关闭，启用后受允许时段、最近来信、间隔和每日次数控制。先持久化一次尝试，再生成与发送；不确定送达时暂停，直到新入站会话恢复。新增聊天节奏不改变这个投递策略。

长期记忆只接收用户明确提交的内容，当前不自动提取、不配置向量数据库。未来应优先增加总长度预算和可视化编辑，再按实际规模评估检索。
